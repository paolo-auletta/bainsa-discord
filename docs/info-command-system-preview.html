/member-info /board-info /project-info Summary contract

Info commands, as one system.

Every lookup leads with identity and scope, groups related facts in a stable order, and ends with quiet provenance. The system stays compact without flattening richer project information or mixing board authority with Discord synchronization problems.

The shared reading order
  1. Identity and current scope
  2. Entity-specific relationships
  3. Private or health context, when authorized
  4. Source and freshness marker

/member-info

Compact event card

A fast identity and access summary. The member reference is normalized before rendering, assignments have explicit empty states, and the same ordered facts become the top of member update and removal panels.

The user’s recorded name remains readable beside a safe Discord mention. Mentions never notify because every payload disables allowed mentions.

/project-info

Private workspace document

The intentional system variant. Project records need more narrative room, stable links, team grouping, and authorized internal context, so they use the bounded document primitive while preserving the same identity → scope → relationships → provenance sequence.

Public summary and conclusion remain distinct from internal working and handover notes. The domain service decides which groups the caller may see before rendering.

Grouped hierarchy

Identity and scope stay above links, people, narrative, and internal context. Related rows remain visually tight.

Privacy is structural

Internal sections are labeled and omitted entirely for callers who are not authorized; they are never merely hidden with styling.

Deterministic limits

The document preserves title, scope, and provenance, then shortens long teams and narrative sections with explicit counts.

One summary contract, more than one surface.

The visual family is enforced upstream. Each entity formatter first produces normalized, privacy-filtered groups; the info response and its update panel then render those same groups. Panels add only staged comparisons.

Domain facts

Database records, resolved Discord references, caller authorization, and synchronization observations.

  • No raw user objects
  • No private-field leakage
  • No renderer-owned authorization
Canonical entity summary

Stable identity, scope, ordered groups, intentional empty values, provenance, and deterministic truncation.

  • Member summary
  • Board roster + separate health report
  • Project record summary
Info or update renderer

Info shows current state. Update panels preserve the same labels and order, annotating only changed values.
